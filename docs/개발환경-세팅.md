# 개발 환경 세팅

GitHub에서 저장소를 받은 뒤 누구나 같은 환경에서 실행하기 위한 방법이다. 근거는 개발기획서 10.2(uv), 11.2(Docker Compose 팀 공통 환경), 11.3(환경변수), 13.1(저장소 구조)이다.

> **현재 상태 (2026-10-20)**: 저장소에는 `docs/`와 `backend/app/engine/`만 있다. 아래에 나오는 `backend/pyproject.toml`, `backend/uv.lock`, `backend/.env.example`, `backend/Dockerfile`, `docker-compose.yml`, `.gitignore`는 백엔드 B가 프로젝트 기반을 만들 때 추가한다(15.1). 그 전까지는 [임시 방법](#5-임시-방법-기반-파일이-생기기-전)을 쓴다.

## 1. 미리 설치할 것

| 도구 | 용도 | 확인 명령 |
|---|---|---|
| Git | 저장소 받기 | `git --version` |
| Docker Desktop | DB·API를 모두 같은 환경으로 실행 (11.2) | `docker compose version` |
| uv | 파이썬 버전·패키지 관리 (10.2) | `uv --version` |
| Node.js 20 이상 | 프론트 담당만 | `node --version` |

uv 설치:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

파이썬은 따로 설치하지 않아도 된다. uv가 `pyproject.toml`에 적힌 버전(3.12)을 알아서 받는다.

## 2. 저장소 받기

```bash
git clone https://github.com/dlfkdLR/SEONBI.git
cd SEONBI
git switch dev          # 작업 브랜치 (13.2: main ← dev ← feat/<기능>)
```

`dev` 브랜치는 아직 없다. 처음 만드는 사람이 `git switch -c dev && git push -u origin dev`로 만든 뒤부터 위 명령을 쓴다. 기능 작업은 `git switch -c feat/<기능>`으로 따로 브랜치를 만들어 PR을 올린다.

## 3. 방법 A — Docker Compose로 전체 실행 (권장)

DB와 API를 모두 같은 버전·설정으로 띄운다. 프론트 담당이나 백엔드 전체 흐름을 확인할 때 쓴다.

```bash
cp backend/.env.example backend/.env     # Windows: copy backend\.env.example backend\.env
docker compose up --build                # 처음, 또는 의존성이 바뀐 뒤
```

- API: http://localhost:8000 (문서: http://localhost:8000/docs)
- 헬스 체크: http://localhost:8000/api/health → `{"status": "ok", "db": "ok"}`
- DB: `localhost:5432` (DB 도구로 직접 볼 때만)

자주 쓰는 명령:

| 상황 | 명령 |
|---|---|
| 평소 실행 | `docker compose up` |
| 끄기 | `docker compose down` |
| **DB 모델이 바뀐 커밋을 받았을 때** | `docker compose down -v` 후 `docker compose up` (DB 초기화) |
| 같은 환경에서 테스트 | `docker compose run --rm api uv run pytest` |

`backend/app` 폴더는 컨테이너에 연결되어 있어서 코드를 고치면 바로 반영된다(`--reload`).

## 4. 방법 B — 로컬 파이썬으로 실행 (엔진·AI 작업용)

엔진처럼 DB 없이 돌아가는 코드를 빠르게 테스트할 때 쓴다.

```bash
cd backend
uv sync                 # .venv를 만들고 uv.lock에 고정된 버전 그대로 설치
uv run pytest           # 테스트
uv run ruff check .     # 린트
uv run mypy app/engine  # 타입 검사 (engine은 strict)
```

- `uv run <명령>`은 가상환경을 켜지 않아도 `.venv` 안에서 실행된다.
- 가상환경을 직접 켜고 싶으면: `source .venv/bin/activate` (Windows: `.venv\Scripts\activate`)
- 패키지를 추가할 때는 `pip install` 대신 `uv add <패키지>`를 쓴다. 그래야 `pyproject.toml`과 `uv.lock`이 함께 바뀌고 팀원도 같은 버전을 받는다. 두 파일을 같이 커밋한다.
- API를 로컬에서 띄울 때는 DB만 Docker로 실행한다: `docker compose up db` → `uv run uvicorn app.main:app --reload`

## 5. 임시 방법 (기반 파일이 생기기 전)

`pyproject.toml`이 아직 없을 때 엔진 코드만 돌려 보는 방법이다. 기반 파일이 들어오면 4번 방법으로 바꾼다.

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install numpy scipy  # 엔진은 numpy와 scipy를 둘 다 쓴다
python -c "from app.engine import posterior; print('ok')"
```

- **numpy만 설치하면 안 된다.** `posterior.py`가 `scipy.special.gammaln`을 쓰므로 import에서 오류가 난다.
- 이 방법은 버전이 사람마다 달라질 수 있어서 팀 공통 환경으로는 쓰지 않는다(11.2).

## 6. 환경변수 (`backend/.env`)

`backend/.env.example`을 복사해서 쓴다. 기본값만으로 LLM 키 없이 전체 흐름이 돈다(Fake LLM).

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DATABASE_URL` | `postgresql+asyncpg://seonbi:seonbi@db:5432/seonbi` | Compose 안에서는 호스트가 `db`. 로컬 실행이면 `localhost` |
| `LLM_MODEL_FAST`, `LLM_MODEL_QUALITY` | `fake:default` | 실제 LLM을 쓸 때 `gemini:gemini-2.5-flash` 등 (6.4) |
| `GEMINI_API_KEY` 등 | 비움 | 실제 LLM을 쓰는 사람만 자기 `.env`에 넣는다 |
| `AI_DAILY_QUOTA_PER_CLIENT` | `50` | 12.2 |

**API 키는 `.env`에만 넣고 절대 커밋하지 않는다.** `.env`는 `.gitignore`에 들어 있다. 키를 채팅·문서·코드에 붙여 넣었다면 재발급한다.

## 7. 올리지 않는 것

| 경로 | 이유 |
|---|---|
| `.venv/` | 운영체제마다 다르다. 각자 `uv sync`로 만든다 |
| `backend/.env` | API 키가 들어간다 |
| `__pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/` | 실행할 때 생기는 캐시 |
| `node_modules/` | 프론트 의존성. `npm install`로 만든다 |

`pyproject.toml`, `uv.lock`, `.env.example`은 **올린다.** 이 파일들이 "모두 같은 환경"의 기준이다.

## 8. 자주 생기는 문제

| 증상 | 원인·해결 |
|---|---|
| `ModuleNotFoundError: scipy` | numpy만 설치함 → `uv sync` (임시 방법이면 `pip install scipy`) |
| 테이블·컬럼이 없다는 DB 오류 | 다른 사람이 모델을 바꿈 → `docker compose down -v` 후 다시 실행 (11.2) |
| 포트 5432 / 8000이 이미 사용 중 | 로컬에 다른 PostgreSQL·서버가 켜져 있음 → 끄거나 Compose 포트를 바꾼다 |
| `uv sync` 후에도 패키지 버전이 다름 | `uv.lock`을 최신으로 받지 않음 → `git pull` 후 다시 `uv sync` |
| 모든 요청이 `400 CLIENT_ID_REQUIRED` | 요청에 `X-Client-Id` 헤더(UUID)가 없음 (3.1, 7.1) |
