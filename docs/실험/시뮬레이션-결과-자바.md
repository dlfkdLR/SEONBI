# 엔진 시뮬레이션 결과 — 자바 엔진 재현 (개발기획서 14장)

`backend/src/test/java/com/seonbi/engine/sim/Simulation.java`를 실제로 돌려 얻은 수치다. 파이썬 참조 구현의 실험(`docs/실험/시뮬레이션-결과.md`)을 같은 설계로 자바 엔진(`com.seonbi.engine`)에서 다시 돌렸다. 아래 표는 프로그램 출력을 그대로 옮겼다.

```
cd backend
./gradlew simulate -Pargs="--scenario both --users 200 --seed 42"
./gradlew simulate -Pargs="--scenario both --users 200 --seed 42 --noise 0.1"
```

## 1. 파이썬 실험과 같은 점·다른 점

- **같은 것**: 두 문제(구매형·진로형, 선택지 4개·기준 5개), 두 전략(`eig` = 엔진 전체의 질문 선택, `random` = 무작위 기준 쌍·무작위 유형), 종료 규칙 5.10, 입자 수 4,000, 사용자 200명, 기본 시드 42, 같은 질문 수 3·5·7 시점 평가, 노이즈 ε = 0과 0.1.
- **다른 것**: 난수 생성기가 다르다(파이썬은 numpy `default_rng`, 자바는 `Well19937c`). 그래서 같은 시드여도 가상 사용자의 정답 가중치와 응답이 같지 않고, **사용자별 값은 재현되지 않는다.** 평균 수준에서 비교한다.
- **결정적 부분의 일치**: 정규화·우도·EIG·전환점 등 난수가 없는 계산은 `engine-reference/golden/`의 골든 파일로 1e-9 안에서 같음을 이미 확인했다(테스트 `*GoldenTest`). 이 실험은 그 위에서 난수가 들어간 전체 흐름이 같은 결론을 내는지 보는 것이다.

## 5. 해석

**파이썬과 같은 결론이 나온 점**
- 같은 질문 수(3·5·7문항)에서 MAE는 4개 조건 × 3개 시점 = 12개 칸 모두에서 EIG가 낮다. 짝 비교 차이는 0.014~0.031이고 표준오차(0.003~0.004)의 3~10배다.
- 종료 규칙을 적용하면 EIG가 더 일찍 끝난다(구매형 4.29 vs 5.15, 진로형 5.34 vs 7.23 문항). 그런데도 MAE는 낮다.
- 진로형에서 EIG의 질문 수가 랜덤보다 크게 적은 것(5.3~5.5 vs 7.2~7.6)도 파이썬과 같다.

**수치가 조금 다른 점 (난수 생성기 차이로 보이는 범위)**
- 절대 MAE는 파이썬보다 구매형에서 0.003~0.007 높게 나왔다(예: 구매형 ε=0 eig 0.084 vs 0.077). 표준오차는 0.003이라 파이썬의 두 배 안팎이고, 사용자 표본이 달라서 생기는 차이와 구분되지 않는다. 엔진 이식 오류인지 표본 차이인지는 이 실험만으로 가를 수 없다. 오류 여부는 골든 파일 대조(결정적 계산)로 확인했다.
- 1위 적중률은 칸마다 파이썬과 방향이 갈린다(구매형 ε=0 eig 0.910 vs 0.950, 진로형 ε=0 eig 0.875 vs 0.845). 이는 표준오차(0.02~0.03) 안이다.

**EIG가 낫다고 말하기 어려운 점 (파이썬과 같음)**
- 1위 적중률의 우위는 일관되지 않다. 같은 질문 수 표에서 구매형 ε=0의 3문항(0.840 vs 0.855), 구매형 ε=0.1의 3·5문항(0.815 vs 0.865, 0.850 vs 0.865)은 랜덤이 같거나 높다. 진로형(ε=0, 0.1)에서는 EIG가 높은 칸이 많지만, 이것을 "노이즈가 있어도 적중률이 높다"는 근거로 삼기에는 두 번의 실험(파이썬·자바) 결과가 서로 방향이 다르다.
- 따라서 적중률 우위는 **입증되지 않았고**, 정확도 근거는 MAE(가중치 추정 오차)로 삼는다.

**한계**
- ε=0은 가상 사용자가 엔진이 가정한 모형 그대로 답하는 유리한 조건이고, ε=0.1도 실제 응답 분포를 대표하지 않는다. 절대 수치는 파일럿(14장)으로 다시 확인해야 한다.
- `eig`는 EIG 하나가 아니라 초기 슬라이더·미등장 기준 우선·상황형 할당·연속 금지 규칙을 포함한 엔진 전체다.
- 랜덤 기준선은 고정 순서 설문이 아니라 매번 무작위 기준 쌍을 묻는 방식이고, 확인한 문제는 두 가지뿐이다.
