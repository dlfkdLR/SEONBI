# 선비

내 선호를 발견하고, 선택이 바뀌는 조건을 확인하는 PC 웹앱입니다.
Figma의 흑백 레이아웃과 한글 산세리프 타이포그래피를 React로 구현했습니다.
**로그인·회원가입·계정 메뉴는 없습니다.** 마지막 사용자 지시에 따라 브라우저별 기록 저장으로 구현했습니다.

## IntelliJ IDEA에서 열기

1. **File → Open**에서 이 `seonbi` 폴더를 선택합니다. `package.json`이 들어 있는 폴더를 열면 됩니다.
2. 프로젝트 Node.js 런타임을 선택합니다. 이 컴퓨터에서는 `/usr/local/bin/node`가 확인되었으며, Node.js 24.14.0입니다. 다른 컴퓨터에서는 해당 컴퓨터의 Node.js를 선택하세요.
3. 오른쪽 위 실행 구성에서 **01 Install dependencies**를 한 번 실행합니다. 잠금 파일 기준으로 `npm ci`를 실행합니다.
4. **02 Seonbi dev**를 선택하고 ▶를 누릅니다. http://127.0.0.1:5173 에서 확인할 수 있습니다.
5. **03 Seonbi build**, **04 Seonbi unit tests**, **05 Seonbi typecheck**, **06 Seonbi browser tests**도 실행 구성에 포함되어 있습니다.

공유 실행 설정은 `.run/`에 있습니다. 사용자별 Node.js 경로·창 배치·최근 파일 정보는 공유하지 않습니다. IntelliJ 실행 구성이 보이지 않으면 `package.json`의 `dev` 옆 실행 버튼 또는 IDE 터미널의 `npm run dev`를 사용할 수 있습니다.

이 컴퓨터의 IntelliJ IDEA는 2026.2.1로 확인했습니다. [JetBrains 공식 문서](https://www.jetbrains.com/help/idea/run-debug-configuration-npm.html)의 npm 실행 구성 방식을 따릅니다. IDE 화면에서 ▶ 실행을 직접 검증한 상태는 아니며, 같은 명령을 CLI에서 검증합니다.

## 실행

Node.js 22.12 이상 또는 24 이상을 권장합니다.

```sh
npm ci
npm run dev
```

개발 주소: http://127.0.0.1:5173

```sh
npm run build       # TypeScript 검사와 프로덕션 빌드
npm run preview     # 빌드 미리보기
npm test            # 계산 로직 테스트
npm run test:e2e    # 실제 Chrome 브라우저 흐름 테스트
```

E2E는 macOS에 설치된 Google Chrome을 우선 사용합니다. 다른 환경에서는 `npx playwright install chromium`으로 브라우저를 설치해주세요. SPA 배포 시 `/decisions/...` 요청을 `index.html`로 되돌리는 설정이 필요합니다.

## 동작하는 기능

- 결정 목록·상태 필터, 생성, 제목/설명 수정, 삭제, 복제
- 선택지 2~8개와 평가 기준 2~7개를 자유롭게 구성
- 선택지 추가/이름 변경/삭제에 따른 표의 행 변경, 기준 추가/수정/삭제에 따른 열 변경
- 숫자, 단계 라벨 3~7개, 순위 및 동순위, 예/아니요 입력
- 이름을 바꿔도 ID로 연결된 기존 입력값 유지
- 숫자형 필수 조건과 선택지별 충족 여부를 지정하는 태그 조건
- 조건 미충족 선택지 제외, 잘못되거나 미완성인 입력에 대한 검증
- A/B 기준 비교, 양방향 슬라이더, 상황형 질문, 건너뛰기, 답변 수정, 추가 질문
- 답변·건너뛰기 이력 전체로 중요도 질문의 중복을 방지하고, 새 질문이 없으면 결과로 이동
- 답변을 반영한 중요도·점수·1위 확률·안정성·전환 조건 계산
- 가중치 합 100%를 유지하는 시뮬레이션 및 민감도 그래프
- 최종 선택과 메모 저장, 확정 후 수정 차단, 복제 후 다시 시작
- Markdown 다운로드, 브라우저 인쇄를 통한 PDF 저장
- localStorage 자동 저장 및 새로고침 후 복원
- 키보드 탐색, 접근성 라벨, 모달 포커스 관리와 Escape 닫기

직접 만든 결정이 없으면 **노트북 예시 1개**가 표시됩니다. 새 결정을 만들면 예시는 사라지고, 직접 만든 결정을 모두 삭제하면 예시 1개가 다시 표시됩니다. 기존 브라우저 기록에도 같은 규칙을 적용하며 직접 만든 기록은 보존합니다. 노트북 제품명과 수치는 시연용이며 최신 제품 정보가 아닙니다. 새로 만든 결정에는 노트북 항목이 자동으로 들어가지 않습니다. 기본 기준 제안은 사용자가 고른 결정 분류의 정적 목록이며 AI 추천으로 표시하지 않습니다.

## 데이터와 서버 연결 범위

현재는 **프론트엔드와 브라우저 내 참조 분석을 포함한 로컬 실행 버전**입니다. FastAPI·PostgreSQL·LLM 서버를 구축하거나 연결한 상태는 아닙니다.

- 브라우저별 UUID는 `seonbi.client-id`, 결정 데이터는 `seonbi.decisions.v1`에 저장합니다.
- 같은 브라우저의 동일한 origin에서만 기록을 확인할 수 있습니다. 사이트 데이터 삭제 시 기록이 사라집니다. 기기 간 동기화나 계정 인증 기능은 없습니다.
- `src/data/local-repository.ts`는 데이터 접근을 담당하고 `src/data/hooks.ts`에서 TanStack Query에 연결합니다.
- `src/api/client.ts`에는 `X-Client-Id`, JSON/파일 응답, 오류 처리 및 요청 전송 계층이 있습니다. `src/api/endpoints.ts`는 로그인 제외 30개 API의 경로와 메서드를 첨부 명세대로 정의합니다. `.env`의 `VITE_API_BASE_URL`을 입력하는 것만으로 서버 모드로 전환되지는 않습니다. 저장소 구현을 서버 API로 교체해야 합니다.
- 사용자 제공 개발기획서 v0.4와 별도 API 목록의 메서드/경로가 일부 다릅니다. 최종 사용자 지시대로 **첨부 API 명세의 경로·메서드를 우선**합니다. 로그인은 제외합니다. 실제 백엔드 브랜치의 차이 및 미확정 스키마는 [API 계약 문서](docs/API-CONTRACT.md)에 정리했습니다.

## 참조 분석의 범위

`src/domain/engine.ts`는 UI를 실제 데이터로 실행하기 위한 TypeScript 참조 구현입니다.
시드가 고정된 Dirichlet 입자 4,000개, Bradley–Terry 비교, 정규화한 슬라이더 우도, 상황형 로지스틱 우도로 중요도를 추정합니다. 필수 조건으로 제외되지 않은 선택지만 순위·확률에 반영합니다. 질문 시작 시 숫자 범위를 고정하고, 범위 밖 값은 0~1로 제한합니다. 전환 조건은 두 점수의 교차점을 구한 뒤 전체 선택지 중 1위가 바뀌는지 확인합니다.

프로덕션 엔진과 동일하다는 의미는 아닙니다. 재샘플링/MH 이동, 전체 후보 EIG 및 종료 기준의 세부 규칙, 시뮬레이션 보정, 서버 상태 전이 검증은 아직 기획서 전체를 구현한 상태가 아닙니다. 로컬 질문 선택은 축소한 입자 집합과 세 유형의 질문 후보를 사용합니다. 기준 유형/방향/척도를 변경하면 관련 답변을 무효화하며, 서버의 더 세밀한 무효화 규칙과는 차이가 있습니다. 결과 화면과 내보내기에 로컬 참조 분석임을 표시했습니다. 서버 연결 시 이 참조 계산 대신 서버 분석 응답을 사용해야 합니다.

## 구조

```text
src/
  api/           첨부 API 명세의 경로·메서드, 요청 전송 계층
  components/    실제 사용하는 버튼·폼·모달·공통 레이아웃
  data/          브라우저 식별, 저장소, Query 훅, 예시 데이터
  domain/        데이터 타입, 참조 계산, 계산 테스트
  lib/           파일 내보내기, 임시 UI 상태, 한글 조사
  pages/         결정 목록, 4단계 설정, 질문, 결과, 시뮬레이션
  styles.css     Figma 색상·간격·타이포그래피와 인쇄 스타일
tests/           전체 사용 흐름에 대한 Playwright 테스트
```

디자인 검증 기준: Figma에서 직접 조회한 내 결정(`10:12`), 주제와 선택지(`10:13`), 값 비교(`10:15`), 질문(`10:17`)의 코드·스크린샷을 기준으로 구현했습니다. 나머지 화면은 Figma Starter 호출 한도로 직접 재조회하지 못해 기존 설계 생성 자료와 기획서를 사용했습니다. 모든 화면에 대한 최신 픽셀 일치를 검증한 상태는 아닙니다.

프레임워크 설정 참고: [Vite](https://vite.dev/guide/), [Tailwind CSS Vite 플러그인](https://tailwindcss.com/docs/installation/using-vite), [React Router](https://reactrouter.com/start/modes).
